# Enterprise GTM AI — development checkpoint

This is the single source of truth for what is built, what has been verified, and what should happen next. Update it at the end of each meaningful milestone so future work continues from the current state instead of repeating completed work.

## Product direction agreed with the user

Build an economical, agent-led outbound workspace for a one-person agency serving multiple clients. The user can also prospect for the agency itself, but agency research and each client's work must stay in separate contexts. Calling should use a provider selected per client and target market, with the target-region caller ID used only when the provider account and local rules allow it.

For a client campaign, the agent should use that client's offer and ideal customer profile (ICP), accept detailed but optional locations per search (country, state/province, city, local area), find suitable companies and relevant buying signals, identify likely decision-makers and source-backed contact details, explain qualification, and prepare personalized outreach. Signals must be relevant to the client's offering; the product must not be limited to SAP or cybersecurity. Public data only, with sources and uncertainty shown; never guess email addresses.

Email is part of the product. The first version requires the user to review and confirm each batch; the sender should be replaceable later when the company domain is ready. CRM integration should be vendor-neutral: a common company/contact format with replaceable connectors for each CRM, rather than making a single provider mandatory. CRM integration should precede calling. Prefer open-source and low-cost components where practical, while accounting for setup and upkeep. Start with manual calling; AI voice, contract extraction, broad CRM coverage, and deep analytics are later work. Reports and recommendations must be clearly separated by agency and client.
